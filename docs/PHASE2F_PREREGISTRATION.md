# Phase 2f 사전등록 — 추세 전환 롱숏과 포지션 데이터

기준일: 2026-10-20 KST. 상태: **등록됨, 결과 보기 전.** 근거: [Decision 0026](decisions/0026-register-phase2f-long-short-positioning.md).

## 1. 목적과 배경

사용자 요청(2026-10-20)은 두 가지다.

- 추세 변화에 따라 롱과 숏을 바꾸고, **하락장에서는 숏 위주**로 운용한다.
- 아직 쓰지 않은 정보로 탐색한다.

이미 시험한 것과 겹치는 부분:

- MA200(현재 관측 중)은 이미 롱숏이다. 200일 평균 아래면 숏이다. 2022~2026 개발 데이터에서 롱은 +340.5, 숏은 −79.6 USDT였다(Decision 0016).
- Phase 2d F5(종목별 SMA 롱숏)와 F4(횡단면 롱숏)는 개발 게이트를 통과하지 못했다.

이번 등록에서 새로 시험하는 것:

- **비대칭 비중:** 상승·하락 구간에 서로 다른 크기로 진입한다. 시장 국면은 BTC 추세 또는 종목 자체 추세로 판단한다.
- **하락장 알트 숏:** 하락 국면에서는 가장 약한 알트를 숏한다. 하락장에서 알트가 BTC보다 더 떨어지는 경향을 노린다.
- **포지션·주문 흐름 데이터:** 미결제약정, 상위 트레이더·전체 계정 롱숏 비율, 테이커 매수 비중이다. 이 데이터는 지금까지 어느 기간에서도 계산하거나 본 적이 없다.

## 2. 데이터 (동결)

- **가격·거래대금·펀딩:** Phase 2d 무기한 패널. 해시 `8f68ecb0…`, 2019-09~2026-09이고 상장폐지 종목을 포함한다.
- **테이커 매수 비중:** 같은 1d 캔들 원본의 taker buy quote volume ÷ quote volume.
- **포지션 지표:** `data.binance.vision` `futures/um/daily/metrics`의 5분 데이터를 하루 한 행으로 줄인다(`v3/phase2f/data.py`).
  - `oi_value`: 그날 마지막 미결제약정(USDT).
  - `top_ls`: 상위 트레이더 포지션 롱숏 비율의 그날 평균.
  - `acct_ls`: 전체 계정 롱숏 비율의 그날 평균.
- **대상 종목:** 2019-09~2026-09에 한 번이라도 무기한 거래대금 상위 20위에 든 195종목.
  - 이 목록은 내려받을 범위만 정한다. 전략은 결정 시점의 순위만 쓴다.
- **동결:** 원본 파일마다 SHA-256을 남기고, 줄인 파일 전체의 해시를 `metrics-manifest.json`에 개발 전에 기록한다.
- **시점:** d일 지표는 d일 안에 찍힌 행만 쓴다. d일 종가에 결정하고 d+1일 시가에 체결하므로 미래 정보를 쓰지 않는다.

## 3. 기간

| 구간 | R1·R2·P3 | P1·P2·P4 (포지션 지표) |
|---|---|---|
| **개발** | **2020-07-01 ~ 2023-12-31** | **2022-01-01 ~ 2023-12-31** |
| **검증** | **2024-01-01 ~ 2026-09-29** | 같음 |

**검증 구간 오염을 미리 밝힌다.** 깨끗한 과거 holdout은 더 이상 없다.

- 2024년은 Phase 2d 개발 구간(F4·F5 포함)이었다.
- 2025-01~2026-09는 Phase 2d 기준선과 Phase 2e E1으로 이미 봤다. BTC가 −19.6% 하락한 기간이라는 것도 안다.

그래서 아래 장치를 둔다.

- 검증은 2024년(상승)과 2025-01~2026-09(하락) **양쪽 모두에서 수익**을 요구한다. 하락장인 줄 아는 기간에 숏만 맞히는 전략은 통과하지 못한다.
- 포지션 지표(P1·P2·P4)와 테이커 비중(P3)은 어느 기간에서도 계산한 적이 없다.
- **최종 확인은 등록 이후 데이터로 하는 전진 관측이다(§6).** 과거 검증 통과는 전진 관측에 올릴 자격일 뿐이다.

## 4. 공통 규칙

Phase 2d §4와 같다. 무기한 수수료는 5 bps이고, 거래대금 순위별 슬리피지와 실제 펀딩을 반영한다.

- **총노출은 1 이하이고 레버리지는 없다.** 레버리지는 별도 결정이다.
- R2·P 유니버스는 결정 시점 무기한 거래대금 상위 20개다.
- P 전략군은 그날 신호 값이 있는 종목만 쓴다. 그런 종목이 2K개 미만이면 현금으로 둔다.

## 6. 선택과 판정

1. **전략군별 대표:** 개발 구간 순 Sharpe가 가장 높은 설정.
2. **개발 게이트 (대표마다):**
   - D1: 순 Sharpe가 기준선 셋 중 최고 Sharpe보다 높다.
   - D3: PBO ≤ 0.30. 전략군 안 설정들로 CSCV를 하고, 16블록으로 나눈다.
   - D4: 비용을 2배로 해도 순 Sharpe가 기준선 최고 Sharpe보다 높다.
   - D5: 최대 낙폭이 BTC 보유의 최대 낙폭보다 작다.
   - D6: 연도별 순수익이 양수인 해가 과반이다.
3. **검증 게이트 (개발 게이트를 통과한 대표만, 한 번 계산):**
   - V1: 검증 구간 순수익 > 0이고 순 Sharpe ≥ 0.5.
   - V2: 2024년과 2025-01~2026-09에서 **각각** 순수익 > 0.
   - V3: 비용 2배에서도 검증 구간 순수익 > 0.
   - V4: 최대 낙폭이 같은 구간 BTC 보유의 최대 낙폭보다 작다.
   - V5: 개발+검증 전체 일별 수익률의 Deflated Sharpe ≥ 0.95.
     - 시험 수 M=187: Phase 2d 120 + Phase 2e 1 + 이번 66.
     - Sharpe 분산은 이번 66개 설정의 개발 Sharpe를 쓴다.
4. **판정:**
   - **`CANDIDATE`:** 모든 게이트를 통과한 대표가 있다. 여럿이면 개발 Sharpe가 가장 높은 것을 택한다.
     - 다음 단계는 주문 없는 전진 관측이다. 서버 반영은 사용자 승인 후에 한다.
     - 전진 관측 기준(등록일 이후 데이터만): 3개월 중간 점검, 6개월 최종. 순수익 > 0이고, 같은 기간 BTC 보유 대비 Sharpe가 낮지 않아야 한다.
   - **`STOP_NO_EDGE`:** 통과한 대표가 없다.
5. 결과를 본 뒤에 격자·방향·기준·기간을 바꾸면 새 등록이다.

## 7. 보고

결과 보고서에 아래를 모두 싣는다.

- 66개 설정 전체의 개발 성과
- 대표의 연도별 수익, 롱·숏 기여, 회전율, 비용, 펀딩
- 기준선
- 게이트 표
- 검증 표

수익률은 CAGR과 기간 수익을 함께 보고한다.
