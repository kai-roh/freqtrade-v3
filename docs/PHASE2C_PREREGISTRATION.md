# Phase 2c 사전등록: BTC·ETH 저빈도 추세 지속성

기준일: 2026-10-02 KST. 상태: **실행 완료, 결과 `STOP_NO_EDGE`**([Decision 0016](decisions/0016-phase2c-result-stop-no-edge.md)). 아래 본문은 등록 당시 그대로다. 이 문서를 고정한 커밋 이후에만 데이터 확장·시뮬레이터
작성·실행을 한다. 결과를 본 뒤 가설·격자·비용·게이트를 바꾸는 것은 새 사전등록으로만 허용한다.

Phase 2c는 **연구 단계**다. 주문을 내지 않고, 통과해도 실자본을 승인하지 않는다. 사용자는 2026-10-02
방향성 위험을 감수하고 추세 연구로 진행하기로 결정했다(Decision 0014 이후). "edge 없음"과 "판정 보류"는
정상 산출물이다.

## 1. 가설과 설계 근거

> BTC·ETH의 여러 날에 걸친 가격 추세 지속성이, 낮은 회전율로 집행했을 때 수수료·슬리피지·펀딩
> 이후에도 남고, 위험을 맞춘 단순 보유보다 나은가?

- Milestone 1(15분봉 눌림목·돌파, 2026-08)과는 다른 가설이다. 단기 진입 타이밍이 아니라 수십~수백 일
  추세의 방향을 일 단위로 보유한다. Decision 0002가 허용한 "저회전 방향성 레짐 지속성"에 해당한다.
- **확신도 반영은 순노출 크기로 한다.** 같은 자산에 롱과 숏을 동시에 여는 헤징은 순노출만 남기고
  수수료와 펀딩을 양쪽에 낸다. 롱 100 + 숏 40은 롱 60과 경제적으로 같고 비용만 더 크다. 그래서 확신도는
  "얼마나 크게 한 방향으로 들고 있느냐"(아래 선형 매핑)로 표현하고, 손실 최소화는 변동성 기반 크기 축소와
  무포지션 구간으로 다룬다. 손실을 줄이는 장치는 이익도 함께 줄인다. 추세 추종이 기대하는 것은 "작은 손실이
  잦고 큰 이익이 드문" 비대칭이지 손실 없는 이익이 아니다.
- 크립토 시계열 모멘텀에는 선행 실증(Liu·Tsyvinski)이 있으나 현재 Binance에서의 수익성을 보장하지 않는다.

## 2. 규칙 (시뮬레이터 작성 전 고정)

대상은 Binance USD-M `BTCUSDT`, `ETHUSDT` 무기한. 자산별로 독립 계산하고 슬리브를 반씩 쓴다.

- 결정: 매일 00:00 UTC, 그 시각까지 완결된 일봉 종가(23:00 캔들 종가)만 사용.
- 변동성: 최근 60개 일간 로그수익률의 표준편차 `σ_d`.
- 추세 강도: `z_L = ln(C_t / C_{t−L}) / (σ_d · √L)`.
- 신호 매핑 두 가지:
  - **이진(데드밴드)**: `|z| ≥ 0.5`이면 `sign(z)`, 아니면 0(무포지션).
  - **선형(확신도)**: `clip(z / 2, −1, 1)`.
- 변동성 스케일: `v = min(1, 0.25 / (σ_d · √365))`. 연 25% 변동성 목표, 1배를 넘기지 않는다.
- 목표 비중 `w = 신호 × v`, 목표 명목 = `w × 자산별 한도`, 자산별 한도 = 슬리브 / 2. **레버리지 없이 1배 이하.**
- 격자: `L` ∈ {20, 60, 120}일 × 매핑 {이진, 선형} = **6조합**.
- 집행: 00:00 결정 → 01:00 캔들 시가에 taker 체결. 현재 비중과 목표 비중 차이가 0.20 이상이거나, 방향이 바뀌거나,
  목표가 0이고 포지션이 있을 때만 거래한다.
- 일일 손절은 두지 않는다. 위험 통제는 변동성 스케일과 1배 한도다.
- 펀딩: Phase 2와 같은 회계(정산 시각 보유분에 실제 정산률, 직전 마크가격).

**대조군**(격자와 별개, 같은 비용·기간):

- **H0** 무거래.
- **BH-VT** 위험을 맞춘 보유: `w = v`(항상 롱, 같은 변동성 스케일).
- **MA200** 단순 추세 기준선: `sign(C_t − 최근 200일 종가 평균) × v`.

## 6. 판정 (두 비용 regime 모두, walk-forward 연속 계좌 기준)

1. 순수익 > 0, 그리고 **슬리브 기준 연환산 순수익 ≥ 8%**(스트레스 비용). 슬리브가 총자본의 50%면 총자본 기여 약 4%다.
2. 슬리브 기준 MDD ≤ 30%.
3. BH-VT 대비: Sharpe가 같거나 높고 **그리고** MDD가 같거나 낮다(시장 상승 편승 이상의 가치).
4. 검증 창 9개 중 5개 이상 양수(정상 비용).
5. 강건성: 6조합의 전 기간 연속 계좌 중 4개 이상 순수익 > 0(정상 비용).
6. 소수 의존 없음: 가장 좋은 달력연도를 빼도, 가장 좋은 에피소드를 빼도 순수익 ≥ 0(정상 비용).
7. PBO ≤ 0.2(정상 비용).
8. 구현 가능성: 거래소 제약 모드(슬리브 500 USDT, `evidence/phase2b/implementability.json`의 수량 간격·최소 주문을
   현재 값으로 과거에 적용하는 근사)에서도 walk-forward 순수익 > 0, 두 비용 모두.

판정:

- 하나라도 실패 → `STOP_NO_EDGE`.
- 모두 통과, 부트스트랩 95% 하한 > 0(정상 비용) → `PASS_DEV`.
- 모두 통과, 하한 ≤ 0 → `INCONCLUSIVE_DEV`(표본 부족, 판정 보류).

`PASS_DEV`와 `INCONCLUSIVE_DEV`는 7절의 전진 관측 자격일 뿐이다.

필수 보고(게이트 아님): 손익 분해(가격·펀딩·수수료·슬리피지), 롱/숏 기여, 시장 노출 시간 비율, 연 회전율,
자산별 추세 에피소드 수(같은 부호 비중이 이어진 구간), 대조군 비교, MA200 대비, 연도별 성과, 수량 간격의 영향.

## 7. 확인 단계 (등록 이후 데이터)

개발 단계가 `PASS_DEV` 또는 `INCONCLUSIVE_DEV`이면, 마지막 학습 창이 고른 조합을 고정해 2026-10-02부터
**주문 없는 전진 관측**을 최소 182일 한다. 통과 조건: 스트레스 비용 순수익 ≥ 0, MDD ≤ 개발 단계 MDD의 1.5배,
연 회전율이 개발 단계의 2배 이내. 통과해도 Demo 집행은 별도 ADR이 필요하고 실자본은 승인되지 않는다.

## 8. 실행 순서

2. 서버에서 데이터 다운로드, `evidence/phase2c/data-manifest.json` 기록.
3. `v3/phase2c/` 시뮬레이터·평가 작성, 합성 데이터 테스트.

## 9. 알려진 한계

- 개발 데이터는 오염돼 있고(4절), 일 단위 추세는 독립 에피소드가 적다. 판정 보류가 나올 수 있다.
- 2020~2022 강세·약세장이 결과를 좌우할 수 있다. 연도별 보고와 6번 게이트로 확인한다.
- 롱 보유 중 양의 펀딩은 비용이다. 현물 롱 변형은 이번 등록에 포함하지 않는다.
- 슬리브 500 USDT는 가정이다. 연구 지표는 슬리브 대비 비율이라 규모와 무관하지만, 8번 게이트는 슬리브 크기에
  의존한다(BTC 수량 간격 0.001).

## 10. 실행 후 정정 (2026-10-02, 검토 반영)

- §1의 "같은 자산에 롱과 숏을 동시에 열면 수수료와 펀딩을 양쪽에 낸다"는 틀렸다. 같은 계약·같은 정산이면 펀딩은
  한쪽이 내고 다른 쪽이 받아 순명목 기준으로 상쇄된다. 늘어나는 것은 거래 수수료와 증거금·청산 관리 부담이다.
  확신도를 하나의 순포지션 크기로 표현한 설계는 그대로 유효하다.
- 8번 게이트의 거래소 제약 모드는 목표 **보유량**에만 최소 주문금액을 적용했다. 거래소 규칙은 **주문 차액**에
  적용되고, 선물의 reduce-only(감축) 주문은 최소 주문금액에서 면제된다(Binance -4164). 판정 `STOP_NO_EDGE`는
  Sharpe·PBO 게이트(이상 모드)에서 정해졌으므로 바뀌지 않는다. 수정된 규칙으로 다시 계산한 값은
  `research_results/phase2c/ma200-comparison/`에 있다. 기록된 실행은 `--legacy-holding-min-notional`로 재현한다.
- MA200 대조군은 가격이 이동평균 아래면 **숏**이다(롱·현금이 아니다). 시장 노출 시간 100%.
