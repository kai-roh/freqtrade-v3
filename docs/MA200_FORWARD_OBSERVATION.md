# MA200 주문 없는 전진 관측 등록

기준일: 2026-10-02 KST. 상태: **등록됨, 2026-10-03 시작**. 근거: [Decision 0018](decisions/0018-ma200-sleeve-1000-plan-departure.md)
(슬리브 1,000 USDT, 계획 이탈로 얻은 관측 자격), [Decision 0019](decisions/0019-ma200-observation-and-dry-run.md).

## 1. 고정하는 것

- **규칙:** Phase 2c MA200 그대로. 매일 00:00 UTC에 `sign(C_t − 최근 200일 종가 평균) × min(1, 0.25/(σ_60d·√365))`,
  BTC·ETH USD-M 무기한, 자산별 500 USDT 한도(1배 이하), 재조정 임계 0.20, 01:00 UTC 시가 taker.
- **슬리브:** 1,000 USDT(계좌 전체).
- **비용·제약:** taker 5 bps + 슬리피지 2 bps, 실제 펀딩. 주문 단위 최소금액 규칙(무기한 감축 주문 면제)과
  `evidence/phase2b/implementability.json`의 수량 간격.
- **대조군:** 현물 보유(변동성 맞춤, 현물 수수료 10 bps, 펀딩 없음), 선물 보유(변동성 맞춤).
- **시작:** 2026-10-03 00:00 UTC(09:00 KST) 결정, 01:00 UTC(10:00 KST) 가상 체결. 이 시각 이후 데이터만 관측 증거다.

## 2. 운영

- 서버 cron이 매일 11:10 KST(02:10 UTC)에 공개 시세를 갱신하고, 같은 시뮬레이터로 관측 시작부터 가상 계좌를 다시 계산한다
  (`scripts/run_ma200_observation.sh`). 계좌 접근과 주문은 없다.
- Telegram 일일 보고: 포지션, 가상 자산, 오늘·이번 주·이번 달 손익, 대조군 비교, MA200까지의 거리, 오늘 가상 주문, 점검 결과.
  월요일에는 주간 손익표, 매월 1일에는 월간 손익표를 덧붙인다.
- 손익 기간(2026-10-07 수정): 각 일일 보고는 직전 보고(24시간 전 10:00 KST 평가) 이후의 손익이다. 이번 주는 월요일 보고부터,
  이번 달은 1일 보고부터의 합이며 기간별 합계는 누적 손익과 같다. 10-03~10-06 보고는 이 값을 00:00 UTC 이후 1시간 손익으로
  잘못 표시했다(가상 자산·누적 손익·포지션은 정확). 규칙·계좌 계산은 바뀌지 않는다.
- Demo 실제 계좌(Decision 0022): 실행기 기록으로 Demo 자산·24시간/주/월 손익·중단선까지 거리를 함께 보내고, 주간·월간
  손익표에 Demo 열을 둔다. 최신 실행 기록이 26시간보다 오래되면 점검 실패(`live_executor_fresh`).
- 기록: `evidence/ma200-observation/`(서버)에 날짜별 JSON과 `latest.json`.

## 3. 7일 운영 점검 (2026-10-03 ~ 2026-10-09)

사용자는 며칠 운영한 뒤 실거래로 가기를 원한다(2026-10-02). **7일은 수익성을 검증할 수 없다.** 200일 기준 전략은 이 기간에
방향 전환이 없을 수 있다. 이 7일은 운영 점검이며 통과 조건은 운영 항목뿐이다.

- 7일 모두 보고가 생성되고 Telegram으로 전달됨.
- 매일 점검 통과: 무기한·현물 데이터 최신, 펀딩 최신, 가상 주문 건너뜀 0.
- 같은 날을 다시 계산해도 같은 결과(결정론적 재계산).
- 예외 없이 종료.

통과해도 실거래 승인이 아니다. 관측은 7일 뒤에도 계속되며 실거래가 시작되면 실제 체결과 비교하는 기준선이 된다.

**판정(2026-10-09 11:23 KST): 통과(운영 항목 4/4).**

- 보고 7/7일 생성, Telegram 7/7 전달.
- 매일 점검 전부 통과, 가상 주문 건너뜀 0/2.
- 10-09를 서버 이미지로 다시 계산한 결과가 계좌·메시지·점검까지 바이트 단위로 같다. 10-08 로컬 재계산도 같다.
  10-09 로컬(macOS) 재계산은 마지막 자리 1e-13 차이로, 플랫폼 부동소수점 차이다.
- 관측 로그에 예외 0건.
- 기간 손익 표시는 10-03~10-07 보고에서 틀렸고 10-07에 고쳤다(Decision 0022). 판정 항목에는 영향이 없다.
- 7일 동안 신호 변화가 없어(BTC·ETH 롱) 방향 전환 경로는 이 기간에 검증되지 않았다. 해당 경로는 10-02 Demo 검증 10단계로 확인했다.

## 4. 규칙 변경 원칙

- 관측 중 규칙·대조군·비용을 바꾸지 않는다.
- 주간·월간 손익표는 **감시용**이다. 추세 전략의 주·월 손익은 시장 움직임이 대부분이라, 한 주나 한 달 결과로 규칙을 바꾸면
  잡음에 맞추게 된다.
- 개선안은 월 1회 검토에서만 다루고, 채택하려면 새 등록을 하고 **변경 이후 데이터**로 평가한다. 바꾼 뒤에는 이전 관측 기간을
  새 규칙의 증거로 쓰지 않는다.

## 5. 실거래 전 필요 사항 (이 등록의 범위 밖)

1. 실자본 사용 결정(ADR): 계좌 기준 최대 손실 중단선 포함.
2. Phase 1 게이트 5번의 실자본용 재결정(자동 청산 복구 또는 짧은 대응 시간과 담당자).
3. 단일 자산 방향성 주문 경로 구현과 Demo 검증(현재 실행기는 두 레그 캐리용). PostgreSQL 통합 테스트 실제 통과.
4. 선물 거래 권한 API 키, USD-M 지갑 1,000 USDT, 격리 마진 2배(노출은 자산별 1배 이하, Decision 0020).
5. 실거래 체결과 가상 관측의 일일 대사.

## 6. Demo 실행과의 대사 (2026-10-02 추가)

Decision 0020에 따라 Demo 실행기(매일 10:05 KST)와 보호 장치(10분마다)가 같은 MA200(변동성 목표 25%, 슬리브 1,000)으로
Demo 계좌에서 주문한다. 관측 보고는 실행기 기록을 읽기 전용으로 받아 실제 포지션과 가상 포지션의 비중 차를 표시하고,
차이가 자산별 한도의 0.10을 넘으면 점검 실패로 표시한다. Demo BTC 수량 단위(0.0001)가 관측에 쓰는 Mainnet 단위(0.001)보다
작아 작은 차이는 정상이다.
